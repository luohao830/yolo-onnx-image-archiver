# 前端任务进度与结果下载改版设计

日期：2026-06-09

## 背景

当前匿名用户前台围绕任务回执、任务编号、访问口令和凭证查询展开。新的产品方向改为让用户在提交任务后直接查看处理进度、关键日志，并在任务完成后下载结果压缩包。管理员后台需要在任务监控中查看每个任务的详细情况，并能手动下载某个任务的输出结果。

本设计覆盖 `frontend/user-app`、`frontend/admin-app` 以及支撑这些页面所需的后端 API 契约。实现时必须保持现有运行时边界真实，不在 UI 上宣称尚未接通的能力。

## 目标

- 用户前台提供“提交任务 -> 查看进度和关键日志 -> 下载结果压缩包”的单一流程。
- 用户前台移除可见任务回执、任务凭证查询入口和独立查询页。
- 任务处理页显示进度条、阶段状态、关键日志、错误原因和完成后的下载按钮。
- 管理员后台任务监控提供任务列表、任务详情、关键日志和结果下载操作。
- 视觉风格统一为控制台式产品界面：浅色工作区、清晰表单、状态徽标、可扫描表格和明确 disabled 状态。

## 非目标

- 不在本轮设计中改变模型管理、系统配置的业务语义。
- 不引入营销首页、装饰性插画或深色科技展示页。
- 不在用户界面暴露访问口令、内部路径、token 或敏感配置。
- 不假设文件上传、结果下载或高级模式提交已经存在；实现时如补齐 API，需要通过测试验证。

## 用户前台设计

### 页面结构

用户前台保留任务创建入口，并将结果查询能力并入提交后的处理视图。

- 首页展示两种任务模式：人员筛选模式和高级模式。
- 人员筛选页面包含文件选择、当前模式说明和“开始处理”主按钮。
- 高级模式页面包含模型选择、推理参数和“开始处理”主按钮。
- 任务提交成功后，页面进入处理状态区，不展示任务编号、访问口令或回执表格。
- 独立凭证查询入口和查询页从导航与主流程中移除。

### 处理状态区

处理状态区固定展示以下信息：

- 当前状态：created、uploaded、running、completed、failed、canceled。
- 数值进度：0 到 100 的百分比。
- 进度条：随状态或后端返回的 progress 更新。
- 阶段列表：文件接收、排队、推理处理、结果打包、完成。
- 关键日志：展示对用户有意义的阶段事件和摘要。
- 错误状态：失败时展示错误原因，并停止显示下载按钮。
- 取消状态：展示任务已取消，不显示下载按钮。

关键日志必须过滤或避免展示内部路径、访问口令、模型真实宿主路径和敏感配置。可展示的日志示例：

- 任务已进入队列，等待处理器领取。
- 文件解压完成，共识别 128 张图片。
- 正在执行推理处理。
- 已处理 92 / 128 张图片。
- 输出结果压缩包已生成。

### 下载行为

任务状态为 completed 且后端确认结果压缩包存在时，显示“下载结果压缩包”按钮。按钮点击后下载当前任务的 zip 文件。

以下状态不显示可点击下载按钮：

- created、uploaded、running：展示处理中状态。
- failed：展示错误原因。
- canceled：展示取消说明。
- completed 但结果包缺失：展示“结果包不可用”提示。

### 前端内部凭据

如果后端仍需要 `job_code` 和 `access_token` 轮询任务状态，前端可以在当前组件状态或会话存储中保存它们，但不得在 UI 中展示。刷新页面后的恢复策略由实现计划决定；默认不承诺跨刷新恢复任务。

## 管理员后台设计

### 任务监控布局

任务监控页面改为“列表 + 详情面板”结构。

- 左侧或主区域展示任务列表。
- 任务列表列出任务编号、模式、状态、进度、取消请求、结果包状态和操作。
- 选择某个任务后，详情面板展示该任务完整信息。
- completed 且结果包存在时，列表和详情面板都可提供下载入口。
- failed 任务保留重试操作。
- 可取消的任务保留取消操作。

### 任务详情内容

管理员任务详情至少包含：

- 任务 ID 与任务编号。
- 任务模式。
- 当前状态。
- 进度百分比。
- 是否请求取消。
- 错误信息。
- 输入路径或输入摘要。
- 结果目录状态。
- 结果 zip 状态。
- 关键事件日志。
- 可用操作：取消、重试、下载输出结果。

管理员界面可以展示更多运维信息，但仍应避免把密钥或访问口令直接暴露在页面上。

## API 契约

实现时需要补齐或扩展以下能力。

### 公开任务状态

公开任务状态接口需要返回支持前台处理视图的数据：

- `job_code`
- `mode`
- `status`
- `progress`
- `events`
- `error_message`
- `download_ready`

`events` 每项建议包含：

- `id`
- `event_type`
- `message`
- `created_at`
- `payload_json` 中可公开的摘要字段

公开状态接口不得返回访问口令、内部绝对路径或敏感配置。

### 公开结果下载

需要新增或确认一个公开下载端点。该端点应验证当前任务访问凭据，仅在任务 completed 且结果 zip 存在时返回文件。

建议路径：

- `GET /api/jobs/{job_code}/download?access_token=...`

错误处理：

- 凭据错误或任务不存在：404。
- 任务未完成：409。
- 结果包缺失：404 或 409，需在实现中统一。

### 管理员任务详情

管理员任务接口需要支持获取单个任务详情。

建议路径：

- `GET /api/admin/jobs/{job_id}`

返回数据应包含任务基础字段、进度、事件列表、结果包状态和可下载状态。

### 管理员结果下载

管理员下载端点应使用管理员 token 授权，允许下载 completed 且结果 zip 存在的任务输出。

建议路径：

- `GET /api/admin/jobs/{job_id}/download`

错误处理：

- 未授权：401。
- 任务不存在：404。
- 任务未完成或结果包缺失：409 或 404，需在实现中统一。

## 进度计算

如果后端暂时没有精确处理进度，可先用状态兜底计算：

- created：5
- uploaded：20
- running：60
- completed：100
- failed：保持最后进度或 100，视觉上标记失败
- canceled：保持最后进度或 0，视觉上标记取消

如果任务事件或推理摘要中包含 `total` 与 `written`，应优先使用 `written / total` 计算 running 阶段进度。进度值必须限制在 0 到 100。

## 视觉规范

- 背景：`#F8FAFC`。
- 文本主色：`#0F172A`。
- 次级文本：`#475569` 或更深，保证对比度。
- 主操作：`#2563EB`。
- 成功：`#16A34A`。
- 警告：`#D97706`。
- 错误：`#DC2626`。
- 圆角：6 到 10px 为主。
- 卡片只用于实际面板、表格容器、详情面板和重复项。
- 不使用 emoji 作为图标。
- 所有可点击元素需要 hover、focus、disabled 状态。
- 移动端 375px 不得横向滚动，表格需要改为堆叠或卡片布局。

## 测试策略

后端测试：

- 公开任务状态返回 progress、events 和 download_ready。
- 公开下载端点校验访问凭据、任务状态和结果 zip 存在性。
- 管理员任务详情返回事件、进度和结果包状态。
- 管理员下载端点校验管理员授权、任务状态和结果 zip 存在性。

用户前台测试：

- 提交任务后不展示任务编号和访问口令。
- 处理中展示进度条与关键日志。
- completed 且 download_ready 时展示下载按钮。
- failed 或 canceled 时不展示下载按钮。
- 查询页入口被移除或路由行为被明确处理。

管理员前台测试：

- 任务列表展示状态、进度和结果包状态。
- 点击任务展示详情与日志。
- completed 且可下载时展示下载操作。
- failed 任务仍可重试。
- 可取消任务仍可取消。

构建验证：

- `python -m pytest tests/backend -v`
- `npm test`（frontend/user-app）
- `npm test`（frontend/admin-app）
- `npm run build`（frontend/user-app）
- `npm run build`（frontend/admin-app）
